SISTEMA DE GESTÃO DE OBRAS — AJA GRUPO EMPRESARIAL
Pacote do sistema

PRIMEIRA INSTALAÇÃO: USE O KIT
------------------------------
A primeira instalação é feita pelo kit (aja-obras-kit-<versao>.zip): duplo
clique no INSTALAR.cmd. Este pacote sozinho serve para ATUALIZAR, ou para a
instalação manual (plano B), descrita em docs/roteiro-instalacao.md.

O QUE TEM AQUI DENTRO
---------------------
server.js, .next\, node_modules\   a aplicação compilada (não mexer)
runtime\node.exe                    o Node que roda o sistema (vem junto)
versao.txt                          a versão desta release
ferramentas\                        CLI do Prisma e o criador do 1º usuário
scripts\instalar.ps1                instalação inicial (roda uma vez)
scripts\atualizar.ps1               atualização para uma nova release
scripts\ATUALIZAR.cmd               duplo clique da atualização
scripts\backup.ps1                  backup do banco + documentos
scripts\comum.ps1                   funções usadas pelos scripts

ATUALIZAÇÃO
-----------
1. Copie o .zip E o .sha256 da versão nova para D:\aja-obras\pacotes\
2. Duplo clique em D:\aja-obras\ATUALIZAR.cmd e aceite o aviso de administrador.

O script confere a integridade, faz dump do banco, para o serviço, aplica as
migrations, troca a versão e confirma que o sistema respondeu. Se qualquer passo
falhar, ele volta para a versão anterior sozinho.

Pelo PowerShell, como Administrador, é o mesmo que:
  powershell -ExecutionPolicy Bypass -File D:\aja-obras\current\scripts\atualizar.ps1 `
      -Pacote D:\aja-obras\pacotes\aja-obras-<versao>.zip

BACKUP
------
Agendado pela instalação: tarefa "AJA Obras - backup", todo dia às 22:00.

  onde fica    D:\aja-obras\backups\
  log          D:\aja-obras\logs\backup.log
  rodar agora  Start-ScheduledTask "AJA Obras - backup"

O backup fica no MESMO disco dos documentos. Protege contra exclusão acidental
e erro de operação; NÃO protege contra falha do disco, perda da máquina ou vírus
que criptografa arquivos. Copiar D:\aja-obras\backups\ para fora desta máquina
(outro computador ou HD externo) é responsabilidade da empresa.

SE ALGO DER ERRADO
------------------
  logs do serviço      D:\aja-obras\logs\servico-erro.log
  saúde do sistema     http://localhost:3000/api/health
  estado do serviço    Get-Service AjaObras
  voltar de versão     trocar a junction D:\aja-obras\current e reiniciar

O QUE NUNCA FAZER
-----------------
  - Compartilhar a pasta D:\aja-obras\storage\ na rede. Quem abrir a pasta pelo
    Explorer baixa qualquer contrato sem passar pela permissão do sistema.
  - Apagar ou sobrescrever D:\aja-obras\.env. Ele guarda o segredo de sessão e a
    senha do banco; perdê-lo derruba o acesso de todos.
  - Apagar D:\aja-obras\bin\nssm.exe. O serviço do sistema depende dele.
  - Rodar "prisma migrate dev" ou "db push". A atualização usa migrate deploy, e
    só ele aplica exatamente o que falta sem inventar nem apagar.
